## Confirmed email issue

The real `.dev.vars` file is correctly excluded from Git because it contains a Resend secret. However, a fresh clone could start without local email values, the Worker returned only a generic `503`, and the client reduced that failure to a console warning. The operational record was saved, but the visible success toast hid the failed email delivery. End-to-end local verification also found that `vinext dev` did not pass `/api/notifications/email` through the custom production Worker entry and returned a `404` instead.

## Changes made

- Added a non-secret, tracked `.dev.vars.example` with the shared Firebase web key and explicit personal Resend placeholders.
- Added `pnpm check:email` plus a non-blocking `predev` warning.
- Added a non-secret `GET /api/notifications/email` configuration check.
- Added a vinext App Router API route that delegates local requests to the same secured Worker handler used in production.
- Added safe lists of missing variable names to `503` responses.
- Added handling for Firebase and Resend network failures.
- Changed the browser email client to preserve the server error and status.
- Updated every email-triggering workflow to show `saved, but email was not sent` when delivery fails.
- Documented per-developer Resend setup. No real API key is committed or shared.

## Verification after the fix

- Tests: 10 passed, 0 failed, including missing-configuration, safe health-check, test-recipient routing, and provider-network-failure cases.
- ESLint: passed with no findings.
- Production build: passed.
- Local `GET /api/notifications/email`: returned a non-secret `503` configuration report when `.dev.vars` was absent.
- Local synthetic `POST /api/notifications/email`: returned a controlled `503` with missing variable names and the setup action instead of a silent failure.
- No email was sent during the missing-configuration verification.

## Remaining recommendations

- Add browser-level tests for each role and email-triggering workflow.
- Split the largest client bundle using route- or feature-level dynamic imports.
- Add structured production monitoring and alerting before operational use.
- Keep `EMAIL_TEST_RECIPIENT` enabled until GAP approves a verified sending domain and real recipients.
